# 16_l2book/web -- the l2book pages

Static files, no build tooling and no framework, no external requests.
`make wasm` builds `book.wasm`. The venue serves this directory from
`--web-root`; GitHub Pages publishes it at
<https://gburd.github.io/libxtc-examples/l2book/> (`.github/workflows/pages.yml`).

| file | what |
|---|---|
| `index.html`, `app.js` | the landing page: what l2book is, its features and measured numbers, how to run it; its two ladders run the engine (`lob_*`) |
| `console.html`, `console.js` | the console: a simulated market (SIM) on `book.wasm`, or the venue's own books (LIVE) |
| `style.css` | the theme, light and dark (follows the system setting) |
| `book.wasm` | generated by `make wasm`, not committed: `book.c` + `console.c` + `signals.c` + `gorand.c` + `wasm.c`, wasm32, no imports |

Run locally (WebAssembly does not load from `file://`):

```
make wasm WASM_CC=clang
python3 -m http.server -b 127.0.0.1 -d web 8080     # SIM only
./l2book --flow                                      # or the venue: SIM and LIVE
```

## The console

The console reproduces
[intrepidkarthi/orderbook's live console](https://intrepidkarthi.github.io/orderbook/console.html)
on this engine. It has the same layout, the same panels (trade as "you",
your resting orders, tape, a 10-level depth ladder, mid price, order-flow
imbalance, volume delta, top-5 depth imbalance, Kyle's lambda,
surveillance), and the same controls (pause, speed, seed, reset, copy
link, run a spoof, run a flood). Each panel's call link names the C
function that computes it here.

The market behind it is theirs as well: their `cmd/obwasm` ported to C in
`console.c`, with their `pkg/signals` and the spoof and order-to-trade
detectors of `pkg/surveillance` in `signals.c`. The noise trader uses
their parameters, and its draws come from a port of Go's `math/rand`
(`gorand.c`). So a seed opens the same market on both pages: the same
orders, the same prints, the same signal values. `test_signals` and
`check_wasm.mjs` hold that to their console's own output (seed 1, step 79,
and five seeds of 5,000 steps whose tapes are identical print for print).

What differs from theirs, and why:

- **The engine** is `book.c` instead of their Go `pkg/matching`, so the
  digest in the bar is `book_digest`, not their `EngineSnapshot.Digest`
  (different bytes are hashed). The market it digests is the same.
- **LIVE mode.** When a running l2book serves the page, `/symbols`
  answers and a switch offers each symbol's live book. The ladder and tape
  come from the venue's SSE stream (`/md`), and "you" trades as account 1
  through `/order`. The same signal code (`live_*` in `wasm.c`) runs over
  what the venue publishes, sampled every 100 ms.
- **What LIVE leaves out.** The venue's web port has no open-orders or
  cancel endpoint, so "your resting orders" is not listed in LIVE. The
  market data is level 2 (no order ids), so the order-level detectors run
  in SIM only.
- **Nav links.** "Tutorial" and "Docs" become "Run it" and "Numbers"
  (COMPARISON.md): this example has no tutorial or docs pages.

## The landing page

`index.html` follows the structure of
[their landing page](https://intrepidkarthi.github.io/orderbook/): hero,
where to start, what is this, what is an order book, how matching works,
everything it does, built to venue standards and honest about the rest,
and run it. The text is rewritten for l2book. Every number on it comes
from `../README.md` or `../COMPARISON.md`, and "What it does not have"
lists what COMPARISON.md's "What the numbers do not say" says this venue
lacks.
