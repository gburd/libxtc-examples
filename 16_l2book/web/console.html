What this is. The real engine — book.c, the C file each of the venue's book Isolates runs, compiled to a 41 KB WebAssembly module with no imports — matching a market of noise traders, with every panel computed by C (console.c, signals.c) and titled by the function that produced it. The market, the signals and the detectors follow intrepidkarthi/orderbook's console definition for definition, and the flow draws from a port of Go's math/rand, so a seed here opens the market the same seed opens there: same orders, same prints, same signals. Same seed, same market, every time: that is the engine's determinism, demonstrated rather than claimed. Put a seed in the URL (?seed=42) and whoever you send it to opens the same market. LIVE. Served by a running l2book, the switch above shows the venue's own books: levels and prints over SSE (/md), your orders through /order, and the same signal code run over what the venue publishes. Spoof and flood are SIM-only. What it is not. A trading signal. The noise market contains none by construction, and the OFI study found a ~540× R² gap between contemporaneous and predictive even in richer flow. Latency numbers are deliberately absent: browser-WASM timings would be noise presented as measurement — the measured ones live in COMPARISON.md. Adapt it: 16_l2book/ in libxtc-examples — the console's whole market is console.c against book.h.
